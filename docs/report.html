SocioMart

Community Food Marketplace — Project Report

Motive. Every neighbourhood has talented home cooks whose food never reaches neighbours beyond their own floor. SocioMart connects home kitchens with people living in the same society: cooks publish today's menu, neighbours browse a live marketplace, add dishes to a cart and place orders — while sellers manage kitchens, offerings, prices and order status from a simple dashboard. It is built as a real production-style product: secure OTP login, a clean REST API, persistent storage, Swagger docs and a mobile-first single-page app.

1. Project Overview

SocioMart is a full-stack community food marketplace web application. It lets home cooks ("sellers") run a digital kitchen inside their housing society and lets neighbours ("buyers") discover dishes, order them online and track them to delivery — the complete hyperlocal food-ordering loop in one product.

1.1 The motive — why this project exists

  • For home cooks: no tech skills or shop needed — OTP login, create a kitchen, post today's dishes, and start taking orders from a simple dashboard.
  • For neighbours: one place to see every home kitchen in the society, browse dishes, add to a cart and order in a few taps.
  • For the community: extra income for cooks, fresh homemade food for residents, and less reliance on commercial food apps for daily meals.
  • As a learning product: deliberately built to production standards — layered Spring Boot backend, security, validation, real persistence, documented REST API and a polished SPA frontend.

Business rules worth knowing: a buyer's cart (draft order) is locked to the first kitchen they add from — switching kitchens requires clearing the cart; only PENDING (unpaid) orders can be cancelled; sellers only see/modify their own kitchen's data; every error returns a consistent JSON ApiErrorDto.

4. Frontend — how the SPA works

  • Zero build tooling. Plain index.html + css/styles.css + js/app.js served by Spring Boot itself — clone, run, done.
  • Hash routing. A hashchange + load listener re-renders the current view instantly; root / auto-redirects to #/home. Routes: #/home, #/kitchen/:slug, #/search/:query, #/my-orders (cart), #/checkout, #/payment/:id, #/orders, #/order/:id, #/sell, #/profile.
  • 100% click navigation. Bottom tab bar, floating cart bar, cards and buttons set location.hash; forms use delegated submit handlers with preventDefault() — the user never types a URL.
  • Active tab highlighting updates on every route change; cart badge & totals refresh after each action.
  • Auth-aware views. Protected tabs prompt for OTP inline and return the user to the screen they originally tapped.

SocioMart

Community Food Marketplace — Project Report & Setup Guide

Motive. Every neighbourhood has talented home cooks whose food never reaches neighbours beyond their own floor. SocioMart connects home kitchens with people in the same society: cooks publish today's menu, neighbours browse a live marketplace, add dishes to a cart and place orders — while sellers manage kitchens, offerings, prices and order status from a simple dashboard. It is built as a real production-style product: secure OTP login, a clean REST API, persistent storage, Swagger docs and a mobile-first single-page app.

1. Project Overview

SocioMart is a full-stack community food marketplace: home cooks ("sellers") run a digital kitchen inside their housing society; neighbours ("buyers") discover dishes, order online, pay, track the order to delivery and rate it — the complete hyperlocal food-ordering loop in one product.

Why it exists

  • For home cooks: no shop or tech skills needed — OTP login, create a kitchen, post today's dishes, take orders from a dashboard.
  • For neighbours: one place to see every home kitchen in the society, browse, cart and order in a few taps.
  • For the community: extra income for cooks, fresh homemade food for residents.
  • As a learning product: deliberately built to production standards — layered Spring Boot backend, security, validation, real persistence, documented REST API, polished SPA.

What the finished product does today

1. Mobile number → OTP (shown on screen in demo mode) → logged in
2. Browse marketplace: kitchen & dish cards, search, category chips
3. Tap a dish → quantity modal → Add to Order
4. Floating cart bar → cart → Checkout → delivery details → Place Order
5. Payment screen → I HAVE PAID → track order
6. Orders tab: history, detail, cancel (PENDING), reorder, rate ★		 1. Profile → Start Selling (one-tap upgrade)
2. Create kitchen: name, cuisine, description, image
3. Sell dashboard: Offerings / Orders / Kitchen tabs
4. Add dishes with price, description, category
5. Incoming orders live → confirm → ready → delivered
6. Edit prices/availability; pause or delete dishes

3. Architecture & What Was Built

3.1 Layered architecture & project structure

my-first-spring-api/                  (repo root)
└─ my-first-spring-api/               (Maven project)
   ├─ mvnw / mvnw.cmd                 Maven wrapper — no Maven install needed
   ├─ pom.xml                         Spring Boot 4.1.1 · Java 21 · dependencies
   ├─ data/sociomartdb.mv.db          H2 file database (created on first run)
   └─ src/main/
      ├─ java/com/example/my_first_spring_api/
      │  ├─ MyFirstSpringApiApplication.java   (main entry point)
      │  ├─ SecurityConfig.java                (route security rules)
      │  ├─ GlobalExceptionHandler.java        (consistent JSON ApiErrorDto)
      │  ├─ controller/   Auth · Marketplace · Seller · BuyerOrder · BuyerProfile
      │  ├─ service/      Buyer · Kitchen · Marketplace · Order · Otp · Seller
      │  ├─ repository/   Spring Data JPA interfaces (6 repositories)
      │  ├─ model/        9 JPA entities (User, Kitchen, Product, Order…)
      │  ├─ dto/          request/response payloads with validation
      │  └─ exception/    domain exceptions → mapped to HTTP status codes
      └─ resources/
         ├─ application.properties     (port 8081, H2 file DB, Swagger)
         └─ static/  index.html · css/styles.css · js/app.js  (the SPA)

3.3 Data model (6 core entities, 9 tables)

EntityKey fields & relationships
UsermobileNumber (unique), name, flatHouseNumber, role (USER | SELLER)
OtpVerificationmobileNumber, otpCode, expiresAt, verified — short-lived login codes
Kitchenname (URL slug), displayName, cuisine, description, imageUrl, open · seller → User
Productname, description, price, category, imageUrl, available · kitchen → Kitchen
Orderstatus PENDING → CONFIRMED → READY → DELIVERED / CANCELLED · paymentStatus PENDING → PAID · total, delivery fields, rating
OrderItemorder, product, quantity & price snapshots — cart and history lines
Business rules: a cart (draft order) is locked to the first kitchen added from — switching kitchens clears it; only unpaid PENDING orders can be cancelled; sellers only see/modify their own kitchen's data; every error returns a consistent JSON ApiErrorDto.

3.4 Frontend SPA

  • Served by Spring Boot itself — no Node.js, no build step: clone, run, open browser.
  • Hash routing (#/home, #/kitchen/:slug, #/my-orders, #/checkout, #/payment/:id, #/orders, #/sell, #/profile) with bottom tab bar, floating cart bar, auth-aware inline OTP prompts.

cd my-first-spring-api
code .
  • Wait ~1 minute while the Java extensions import the project and download dependencies (watch the blue status bar; trust the authors if prompted).
  • The Maven project is the inner my-first-spring-api folder (contains pom.xml) — open/refresh it if VS Code shows two roots.

Step 3 — Run the app

OptionHow
Easiest — VS CodeOpen MyFirstSpringApiApplication.java → press F5 → choose Java if asked. Or use the Spring Boot Dashboard sidebar → right-click the app → Start.
Terminal — WindowsIn VS Code terminal (PowerShell), from the inner my-first-spring-api folder: .\mvnw.cmd spring-boot:run
Terminal — macOS/Linux./mvnw spring-boot:run

Wait for Started MyFirstSpringApiApplication in the console. The first run downloads dependencies (2–5 min); later runs are fast. The database file data/sociomartdb.mv.db is created automatically.

Step 4 — Open the app & verify it works

URLWhat it is
http://localhost:8081The SocioMart app — boots on #/home with an empty marketplace
http://localhost:8081/swagger-ui.htmlLive API documentation (Swagger UI) · JSON at /v3/api-docs
http://localhost:8081/h2-consoleDB console — JDBC URL jdbc:h2:file:./data/sociomartdb, user sa, blank password
Try the full demo (5 minutes): register with any 10-digit mobile number → the OTP is displayed right in the dialog (demo mode — no SMS setup needed) → log in → Profile → Start Selling → create a kitchen → add 2–3 dishes → in a second browser/incognito window register as a different buyer → add dishes to the cart → checkout → place order → I HAVE PAID → back in the seller window, confirm → ready → deliver the order. That exercises every core feature.

Stop the app: Ctrl+C in the terminal or Stop in VS Code. Factory reset: stop the app and delete the data/ folder — it is recreated empty on next start.
